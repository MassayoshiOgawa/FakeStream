NOTA DE MÉTODO E LIMITES
- Este documento descreve somente o que é visível nas duas imagens anexadas.
- A IMAGEM 1 fornecida tem 380 x 744 px (RGB). A IMAGEM 2 fornecida tem 271 x 523 px (RGB). Essas são as dimensões reais dos arquivos recebidos, não as dimensões nativas garantidas da interface original.
- A tela-alvo informada no briefing é 1080 x 2400 px. As imagens recebidas não têm essa resolução e suas proporções também não correspondem exatamente a 1080:2400. Portanto, não é possível afirmar que um elemento medido na imagem fornecida possuía aquele mesmo número de pixels na tela original do aparelho.
- Neste documento, “medido” significa coordenada observada no arquivo anexado; “aproximado” significa limite visual estimado por causa de antialiasing, compressão, transparência, perspectiva ou baixa resolução; “estimativa escalada” significa projeção matemática, não uma medição nativa.
- As conversões para dp são apenas referências aproximadas. dp (density-independent pixels, ou pixels independentes de densidade) não pode ser recuperado com precisão sem a densidade real usada para capturar/renderizar a interface. Para a IMAGEM 1, a estimativa comparativa usa 380 px de largura como equivalente a 411 dp, ou fator de aproximadamente 1,082 dp por pixel da imagem. Não aplicar essa conversão como especificação definitiva de implementação.
- Cores indicadas como HEX são amostras visuais aproximadas, não uma leitura certificada de cada pixel da interface original. Ícones e letras antialiasados contêm pixels intermediários.
- As duas imagens representam telas distintas/estados distintos. A IMAGEM 1 é a fonte para a tela principal ao vivo e a régua de ações. A IMAGEM 2 é a fonte para comentários e contador de espectadores. Não se deve completar uma imagem com elementos presumidos da outra.
- Não há base visual suficiente para afirmar animações, pulsação, estados temporários, comportamento de toque ou funcionamento. O documento registra aparência estática.
